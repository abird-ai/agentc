# 50 — Build and test

`agentc` takes its design inspiration from pi
(<https://github.com/earendil-works/pi>). It builds as a freestanding C23 static
binary with no libc, its own allocator and its own `_start`, and it is tested by
running the same offline suite on every architecture it ships. This document is
the build matrix, the test surface, the platform support matrix, and the
measurement policy.

Related documents: `.agents/design/00-architecture.md`,
`.agents/design/10-platform.md`, `.agents/design/20-core-agent.md`,
`.agents/design/30-extensibility.md`, `.agents/design/40-tui.md`,
`.agents/design/60-rpc.md`, `.agents/design/61-protocol.md`,
`.agents/design/70-sdk.md`, `.agents/plans/P5-AXES.md`.

## 1. Toolchain and freestanding rules

The driver is GNU make (`Makefile`); the compiler is clang with C23. The base
flags are:

```text
-std=c23 -ffreestanding -fno-stack-protector -fno-builtin
-fno-asynchronous-unwind-tables -fno-unwind-tables -Wall -Wextra
```

Release builds add `-O2 -s` (`-Wl,-x` on Mach-O); test builds add `-O0 -g`.
Linking on Linux is `-static -nostdlib -Wl,--no-dynamic-linker -Wl,-e,_start
-Wl,-z,noexecstack`, with `_start` owned by the tree.

- **Linux and Windows are freestanding include surfaces.** They build with
  `-nostdinc` plus clang's builtin headers and `third_party/freestanding/`
  (`SHIM_INC`). A host libc header cannot leak in through a vendored library.
- **macOS keeps the SDK headers and links libSystem.** The native link is
  `-nostdlib -Wl,-e,_start -lSystem -framework Security -framework
  CoreFoundation`, so `SHIM_INC` is empty and the macOS shims do not shadow the
  SDK headers.
- **The vendored TLS subset is compiled freestanding too.**
  `third_party/mbedtls_glue.c` and the sources in `tools/mbedtls-sources.txt`
  are built with `-O2 -ffreestanding -nostdlib` and
  `-DMBEDTLS_CONFIG_FILE='"mbedtls_agentc_config.h"'` (`.agents/design/10-platform.md`
  §3).
- **The measuring harness is deliberately hosted.** `tools/measure.c` is built
  with the system compiler because it needs `fork`/`wait4`/`getrusage` and a pty.
- `build/version.h` is regenerated from `VERSION` only when its content
  changes; every object depends on it, so a rebuild is cheap when nothing
  changed.
- The static extension registry is generated by `tools/gen-exts.py` from
  `extensions/manifest.json` into `build/exts.c` / `build/exts.mk`; Python is
  optional, and without it no manifest-derived objects are built. Cargo decides
  whether the Rust staticlibs and their force-link flags exist.

## 2. Build matrix

### 2.1 Native goals

| Goal | Output |
| --- | --- |
| `make` / `make release` | `build/agentc` (native: Linux x86-64 or macOS host slice) |
| `make debug` | `build/agentc-debug` (`-O0 -g`, shares the TLS objects) |
| `make test` | `build/test/<name>` golden binaries |
| `make check` | `make test`, the golden suite, `check-ext`, and the registry self-test |
| `make live-net` | `build/net_live` live HTTP/SSE/TLS client (Linux) |
| `make ext-pipeline` | `build/ext_harness` C/Rust extension harness |
| `make release-exts` | `build/agentc` with manifest extensions linked |
| `make windows` | `build/agentc.exe` (default x86-64) |
| `make windows WIN_ARCH=arm64` | `build/agentc-arm64.exe` |
| `make win-tests` | `build/test/<name>.exe` (ARM64 → `build/test/arm64/`) |
| `make wine-check` | Windows golden suite under Wine |
| `make ext-dylib` | `build/extensions/hello.so` / `.dylib` |
| `make win-ext-dylib` | `build/extensions/hello.dll` (+ the no-export companion) |
| `make dyn-check` | dynamic-extension runtime gate under Wine |
| `make bench` | startup/RSS/size measurements |
| `make client` | `build/agentc-client` typed framed-protocol client |
| `make lib` | `build/libagentc.a` PIC SDK archive |
| `make libcheck` | SDK archive + symbol/object deny-lists + PIE host link/run |
| `make libstrict` | asserts the strict archive has no `src/app/*.o` |
| `make libso` / `make pc` | shared library + `agentc.pc` (Linux) |
| `make install-lib PREFIX=…` | SDK headers + archive + `.so` + `.pc` |
| `make install PREFIX=…` | `$(PREFIX)/bin/agentc` |
| `make dist` | `dist/agentc-<os>-<mach>.tar.gz` + `.sha256` |

### 2.2 Native platforms

- **Linux x86-64.** `make` builds the default goal; the tree is hand-tested
  here.
- **macOS.** On a Mac with Xcode command line tools, `make release` builds the
  host slice; `make test` builds the golden binaries and `sh tests/run-built.sh`
  compares them against `tests/data/*.expected`. Intel Macs are not shipped as
  a native target; the x86-64 slice is cross-built.
- **Windows.** `make windows` cross-compiles with LLVM (`clang`,
  `llvm-dlltool`, `lld-link`); the import libraries are generated from
  `src/win/*.def`. `make win-tests` builds the golden executables against
  `src/net/mock.c`.

### 2.3 Cross targets (Makefile)

Because the Linux binaries are freestanding and static, a cross build is a plain
clang invocation with no sysroot:

```sh
make release CC="clang --target=aarch64-unknown-linux-gnu" ARCH_FLAGS=-fno-pic \
     REL_OBJDIR=build/obj/aarch64/release OUT=build/agentc-aarch64
```

The same suite runs for every architecture through the Makefile's
`TEST_RUNNER`/`TST_BINDIR` hooks:

```sh
make check CC="clang --target=aarch64-unknown-linux-gnu" ARCH_FLAGS=-fno-pic \
     TST_OBJDIR=build/obj/aarch64/test TST_BINDIR=build/test-aarch64 \
     TEST_RUNNER=qemu-aarch64
```

macOS cross builds use `make release PLATFORM=mac CC=… MAC_ARCH=arm64` with the
Apple SDK and `-fuse-ld=lld`; `llvm-lipo` merges the slices. Windows cross
builds select the architecture with `WIN_ARCH`.

### 2.4 Nix release-all

`nix build .#release-all` builds every target on one host into
`result-release/bin/`:

```text
agentc-linux-x86_64   agentc-linux-aarch64   agentc-linux-riscv64
agentc-windows-x86_64 agentc-windows-aarch64
agentc-macos-arm64    agentc-macos-x86_64    agentc-macos-universal
```

The flake is a thin entry point: `flake.nix` imports `nix/default.nix`, which
wires `native.nix`, `cross.nix`, `release.nix` and `dev.nix` together. The flake
also exposes `native`, `all`, `macosUniversal`, and the individual
macOS slices; the dev shell carries clang, lld, llvm, GNU make, python3, cargo,
rustc and qemu, plus Wine on Linux. `.github/workflows/release.yml` builds
`.#release-all`, packages one archive per target (binary + `LICENSE`,
`README.md`, `THIRD_PARTY.md`), writes per-archive SHA-256 files, and attaches
the assets to a tag. A `macos-native` job builds and tests the same sources on a
real Mac so the cross toolchain stays honest.

### 2.5 Packaging and install

- `make dist` produces `dist/agentc-<os>-<mach>.tar.gz` and a `.sha256`, with the
  same layout as the release workflow (static binary plus `LICENSE`,
  `README.md`, `THIRD_PARTY.md`).
- `install.sh` downloads the published Linux x86-64 or macOS arm64 archive and
  installs the binary under `AGENTC_PREFIX` (default `~/.local`).
- `install.ps1` downloads the Windows x86-64 zip and installs
  `agentc.exe` under `%LOCALAPPDATA%\agentc`, adding it to the user PATH.

## 3. How tests run

### 3.1 Golden suite

`tests/*.c` are standalone programs linked against the portable base objects
plus `src/net/mock.c` and the platform layer. `tests/run.sh` builds them with
`make test`, runs each under `timeout 20` (prefixed with `TEST_RUNNER` for a
cross target), and compares stdout+stderr byte-for-byte with
`tests/data/<name>.expected`. The runner exports a scratch `HOME` and
`XDG_CONFIG_HOME`/`XDG_DATA_HOME`/`XDG_STATE_HOME` (default `build/golden-home`,
pinned with `AGENTC_TEST_HOME`) so no golden binary reads or writes the
developer's real config; `tests/ext.sh` isolates the same way for the standalone
`ext_test` fixture. `make check` runs the suite, `check-ext` (the
linked extension examples), and `tools/gen-exts.py --self-test`; a cross build
skips `check-ext` because it cannot execute a host-linked harness. On macOS
`sh tests/run-built.sh` runs the already-built binaries.

The suite covers base memory/vector/buffer and string/UTF-8 helpers,
JSON/JSONC/JSON-writer, URL and HTTP parsing (including replay), SSE, the tool
policy and engine, providers and the agent loop, sessions/config/trust, the TUI,
OAuth, MCP, the dynamic-extension lifecycle, and `fuzz_test` — a deterministic
mutation fuzzer over JSONC/SSE/URL (30 000 iterations, fixed-seed xorshift) where
a crash, hang or leak fails the run.

### 3.2 End-to-end (`tests/e2e.sh`)

Builds the stock release and drives a mock Anthropic provider over HTTP/SSE
through a full turn: request → SSE → tool call → tool execution → second
request. It also checks:

- `--continue` replays the persisted transcript without re-running a tool, with
  the session writer producing each message exactly once;
- a truncated turn that still carries a tool call closes it with a synthetic
  error result instead of executing it;
- `--system` hard-replaces the render (sentinel present, core preamble absent)
  in `--dump-wire`;
- strict `--tools` defers an absent `mcp__` name and exits 2 on a real typo;
- trust ordering gates project skills in the system prompt;
- `--list-extensions`, the `info: extensions:` summary, and the extension
  provider row;
- the P5 tool engine: an external `grep` round-trip through a stub `rg` on PATH,
  and `--tools-engine internal` naming the built-in engine in the prompt
  (`.agents/plans/P5-TOOL-ENGINE.md`);
- `tests/tui_e2e.py` and `tests/setup_e2e.py` for the TUI and onboarding flows.

### 3.3 Extensions (`tests/ext.sh`)

`make test ext-pipeline` links the C example, the Rust example (when cargo is
available), the async example and the in-test fixture into `build/ext_harness`.
The harness asserts the hello tool and its veto, the fake provider and its
`fake-model-1` row, the four async tools and each stop path (finish, result
error, fatal, timeout, cancel), and the golden `ext_test` fixture.

### 3.4 MCP (`tests/mcp.sh`)

Drives the real stdio path (`os_spawn` + pipes) against `tests/mcp_mock.py` with
no network and no API keys: server startup, tool listing and calls, environment
expansion, a failed server, and the idle `list_changed` pump.

### 3.4a Test hygiene (`tests/harness.sh`)

The three live suites (`tests/serve.sh`, `tests/e2e.sh`, `tests/mcp.sh`) source
the shared `tests/harness.sh` and call `harness_preclean` before starting any
service and `harness_postclean` from their EXIT trap. It reaps a leftover native
`agentc serve`, a Wine-hosted `agentc.exe serve` (plus `wineserver -k`), and
stale `mock_provider.py`/`mcp_mock.py`, and removes stale `build/serve*` sockets
and pid files. It is conservative by construction: a process is killed only
when it is a descendant of the running suite (`$$`) or an orphan, so a parent's
service — `e2e.sh`'s own mock while it runs `serve.sh` — is never touched; every
wait is bounded and no network is used.

### 3.5 Live network and TLS (`tests/net.sh`)

Builds `build/net_live` with the real Linux backend and runs loopback checks:
plain HTTP GET/POST, SSE, a chunked body, an HTTP/1.0 EOF-delimited body, and a
302 that is returned rather than followed. When `openssl` is present it also
starts a self-signed TLS server: the connection succeeds with
`AGENTC_TLS_VERIFY=0`, and default verification must reject the self-signed
certificate.

### 3.6 Dynamic extensions (`tests/dyn.sh`)

One assertion set with three runtime branches:

- **macOS** — builds `build/extensions/hello.dylib` and loads it with the native
  binary through `dlopen`/`dlsym`/`dlclose`.
- **Windows** — builds `hello.dll` with `make win-ext-dylib` and loads it with
  `build/agentc.exe` through `LoadLibraryExW`.
- **Linux `--wine`** — the same Windows binary and DLL under Wine (with
  `XDG_CONFIG_HOME` injected through a generated `.bat`).

Assertions: the dynamic row loads; `hello_echo` is really registered (strict
policy accepts it while a bogus name is rejected); a broken image, a library
without the entry symbol and a duplicate name each log and continue while hello
still loads; and the loader failure text is the platform one (Windows/Wine:
`not a valid Win32 application (error 193)` and `procedure not found (error
127)`). On plain Linux the native shared object is still built as a PIC/ABI
check and the runtime is skipped because the freestanding static build has no
dynamic loader.

### 3.7 Wine and cross-architecture runs

- `make wine-check` (`tests/wine.sh`) runs the Windows golden suite under Wine,
  skipping cleanly when Wine is absent. It strips Wine bootstrap noise and, once
  the suite passes, reports which real `cmd.exe` assertions ran and that the
  missing `pwsh` case is asserted as a clear error.
- `tests/run-built.ps1` runs the already-built golden executables on a real
  Windows kernel, once per shell for `tools_test` and `modes_test`. It is
  informational: failures print but do not fail the job until the suite has been
  observed green.
- The cross Linux binaries run under qemu-user with no sysroot, in both CI jobs.

### 3.8 CI jobs

`.github/workflows/ci.yml`:

- **linux** (`ubuntu-24.04`): default build, `--version`, `make ext-pipeline`,
  `make check`, the dynamic-extension gate (`ext-dylib`, `win-ext-dylib`,
  `make dyn-check`), the Windows suite under Wine (`make wine-check`),
  `tests/e2e.sh`, `tests/net.sh`, `tests/mcp.sh`, `tests/ext.sh`, `make dist`,
  and a size report.
- **cross**: `nix build .#release-all`, then `make check` under qemu for aarch64
  and riscv64.
- **macos** (`macos-14`): `make release`, smoke, `make test &&
  sh tests/run-built.sh`, `make ext-dylib`, `sh tests/dyn.sh`.
- **windows** (`windows-latest`): `make windows`, smoke, informational
  `make win-tests` + `pwsh tests/run-built.ps1`, `make win-ext-dylib`,
  `bash tests/dyn.sh --windows`.
- **windows-arm64-wine**: `make windows WIN_ARCH=arm64` and the golden suite
  under native aarch64 Wine on an ARM64 runner (non-gating).

## 4. Platform support matrix

| target | builds | offline suite | hand-tested |
| --- | --- | --- | --- |
| Linux x86-64 | yes | golden, e2e, live net/TLS, MCP, extensions | yes |
| Linux aarch64 | yes | golden under `qemu-user` | yes |
| Linux riscv64 | yes | golden under `qemu-user` | yes |
| macOS arm64 | yes | golden, natively on a Mac runner | no |
| macOS x86-64 | yes | cross-built; Mach-O header checked, not executed | no |
| Windows x86-64 | yes | golden under Wine (CI: real `cmd.exe`, missing-`pwsh` error) | no |
| Windows arm64 | yes (PE header checked) | golden under native aarch64 Wine (CI, non-gating) | no |

*Hand-tested* means a person has run that binary for a real session on that
platform, which is not the same as a suite passing in CI. Linux is exercised end
to end, including the cross-built binaries under qemu. macOS and Windows compile
and link, and their CI jobs run the suite and the dynamic-extension runtime
gate, but the macOS TUI, a real Windows kernel and console, TLS against a real
provider, and the ARM64 PE remain unverified by hand. On a real Windows host the
`shell` config key selects the interpreter (`auto` defaulting to `cmd.exe`,
plus `cmd`, `powershell` and `pwsh`, with `AGENTC_SHELL` overriding the file); a
missing requested shell is a clear error, never a silent fallback.

## 5. Measurement policy

`make bench` builds `build/measure` (hosted C) and reports:

- `./build/measure --runs 50 -- ./build/agentc --version` — startup wall time
  and the child's peak RSS;
- `./build/measure --pty -- ./build/agentc --api-key x` — an interactive PTY
  start, sending `/quit` after 0.5 s;
- `ls -l build/agentc` — binary size (the CI `size` step also runs `size`).

Published claims compare `agentc` against a hosted plain-C baseline of the same
core (libc allowed). The useful numbers are the freestanding/no-libc penalty
over ordinary C and the agent-layer cost over a trivial C loop — not the ratio
against a high-level runtime on its own.

## 6. Known unverified areas

- **macOS hand session.** The TUI and platform differences (resize, unicode
  width, Ctrl-C, paste, the owned bottom region, `--tui-mode fullscreen`) are
  not exercised by a person on macOS.
- **macOS entry convention.** The `_start` stub assumes dyld passes
  argc/argv/envp in x0/x1/x2 on arm64 (the x86-64 slice uses the classic
  top-of-stack layout); this is checked at link time, not against a real dyld.
- **macOS x86-64 execution.** The slice is cross-built; only its Mach-O header
  is inspected.
- **SecureTransport.** The API is deprecated (present through macOS 15); the
  target is macOS 12.0 and uses only documented calls. No real HTTPS session
  against a provider has been run by hand.
- **Windows console and shells.** Real console/ConPTY behaviour, real
  PowerShell 5.1 and `pwsh` execution are not verified; Wine ships neither a
  working PowerShell 7 nor real console semantics.
- **SChannel.** Manual certificate validation and the TLS 1.3 credential path
  with a TLS 1.2 fallback retry exist, but TLS 1.3 and the certificate-chain
  error paths have not been exercised against a real provider at runtime.
- **Windows ARM64.** Wine does not emulate a CPU, so the ARM64 PE runs only
  under native aarch64 Wine on an ARM64 runner (non-gating); a real Windows
  ARM64 kernel is unverified.
- **Windows pipe write path.** After the first `PIPE_BUF` chunk, a full request
  pipe can sleep past the write deadline, and a request larger than one
  `PIPE_BUF` can time out; the writability fix belongs in `src/plat/win/sys.c`.
  The macOS parent write end is blocking too, so the same full-pipe probe can
  sleep past the deadline (`.agents/design/10-platform.md` §1.3).
- **Wine is not Windows.** It is a Win32 reimplementation, so a pass under Wine
  does not validate SChannel/TLS, real console behaviour, the Windows shells, or
  the ARM64 PE against real Windows.

## P5 as-built gates (RPC v1, SDK, framed protocol)

The P5 axes add these gates on top of the P6 set; the canonical contracts are
`60-rpc.md`, `61-protocol.md` and `70-sdk.md`, and the progress record is
`.agents/plans/p5-axes/TODO.md`.

| gate | what it proves |
| --- | --- |
| `make check` (incl. `rpc_test`, `frame_test`, `cbor_test`, `proto_test` and the extended `modes_test`/`fuzz_test`) | the JSONL record layer and the frame/CBOR/envelope codecs are byte-exact |
| `tests/rpc_check.py` (via `e2e.sh`) | `--mode rpc` as a stdio subprocess |
| `sh tests/serve.sh` + `tests/proto_client.py` | Unix/TCP/WebSocket/TLS handshake, perms, token, prompt round-trip, cancel, paging, dialogs, attach routing and the bounded multi-session registry; skips cleanly without wine/TLS |
| `make client` | the `agentc-client` tool and synchronous client |
| `make lib` / `make libcheck` | the PIC archive, symbol/object deny-lists, a default-PIE host link and a stable `agentc_mem_live()` |
| `make libstrict` | the strict archive contains no `src/app/*.o` |
| `make install-lib PREFIX=…` | headers + archive + `.so` + `agentc.pc` |

`--mode rpc` JSONL output stays byte-identical through the dispatcher split
(`rpc_dispatch.c`) that `serve` layers framing on; no P5 change altered an
existing golden except the version-string goldens regenerated for a release.
