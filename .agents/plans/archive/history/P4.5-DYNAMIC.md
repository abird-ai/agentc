# P4.5 — optional dynamic extension loading (delivered)

Status: **P4.5a delivered; P4.5b delivered but platform-runtime-gated on CI.**
Decisions D138–D147 in `EXTENSION-HANDOFF.md` (inventory §5.9 there). P4.5 is
committed (`9f4b7db` feature, `9f3c12b` docs); the post-P4 close-out (D148–D151)
is uncommitted until the chair commits it. The files are tracked, so
`nix build .#…` release gates no longer see a dirty-tree source gap.

## Goal

On macOS and Windows the host may load extension libraries from the user's
config directory at runtime; the Linux freestanding static binary keeps its
compile-time stub. No ABI change: the library exports the canonical
`agentc_ext_init` and is adopted like a linked extension.

## Frozen decisions

- **D138:** `plat` gains `os_ext_open/sym/close/available/suffix`. Linux
  `-nostdlib` static returns `-ENOSYS`/`false`/`NULL` with a clear message;
  macOS uses `dlopen(RTLD_NOW|RTLD_LOCAL)`; Windows uses
  `LoadLibraryExW(path, NULL, LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR |
  LOAD_LIBRARY_SEARCH_SYSTEM32)` and fails closed if the flags are unsupported.
- **D139:** one fixed directory `<config home>/extensions/`, suffix
  `.dylib`/`.dll`, stem = extension name `[a-z0-9_.:-]{1,64}`; deterministic
  bytewise order, cap 32; no `extensions.paths`, no project directory, no kill
  switch (`extensions.disabled` filters by name).
- **D140:** the descriptor `out.name` must equal the file stem (fail closed).
- **D141:** a dynamic library is closed exactly once, only when idle:
  registrations removed, `shutdown()` returned, no live async job for the owner,
  no extension callback on the stack (`owner_get()==0` and not pumping). A close
  that cannot happen immediately is deferred to job unlink/pump/shutdown; a
  library still mapped for a live job at shutdown is kept mapped with a warning
  (fallback D141-b: never close is an accepted ADR alternative).
- **D142:** no ABI change. `agentc_ext_adopt` owner-tags the entry phase (entry
  must be descriptor-only and must not register) and rolls the owner back on
  validation failure; `load_all` re-checks a record after a re-entrant unload
  during `init`.
- **D143–D144:** Windows search-order safety as D138; POSIX rejects a
  group/other-writable file and `extensions/` directory; symlinks are followed
  (the permission check makes a hostile symlink require user-level write access;
  TOCTOU residual documented). A loaded extension is trusted native code — no
  sandbox, no crash isolation.
- **D145:** `AgcExtInfo.dynamic` + `(dynamic)` in `--list-extensions`.
- **D146:** dynamic registration runs in all composition sites after
  `register_linked()` and before `apply_config()`, so `AgcExt.order` and
  `extensions.disabled` apply uniformly.
- **D147:** P4.5a is local (fake-loader unit tests + cross compiles); platform
  claims are gated on P4.5b CI runtime jobs (macos-14, windows-latest, Wine
  `make dyn-check`). No "supported" claim from a local green.

### P4.5a delivered deviations

- **Windows keeps the regular-file check.** `agentc_ext_dyn_path_ok()`
  enforces `S_IFREG` on every platform (Windows reports the POSIX mode from
  `GetFileAttributes` in `win/sys.c`); only the group/other-writable half is
  POSIX-only. The plan said "POSIX rejects …"; the delivered check is a
  portable regular-file test plus a POSIX permission test.
- **`agentc_ext_register_dynamic()` is `void`.** It logs candidates and
  failures; callers have nothing to branch on (state is visible through
  `agentc_ext_describe`). The plan left the signature open.
- **The path policy runs twice.** The scan (`dyn_scan_cb`) decides membership,
  and `dyn_register_cb` re-checks `agentc_ext_dyn_path_ok()` immediately before
  `open`, because the scan's `stat` happened in an earlier syscall window.
- **Finding 1 fix — status-provider trampoline.** Status providers are
  registered through a heap `StatusReg` record and `host_status_call`, which
  restores the provider's owner id around the call. A provider that unloads its
  own library mid-snapshot therefore still runs inside a tagged callback: the
  handle is not closed under its own code and the close lands at the pump
  epilogue (`dyn_close_deferred`).
- **Finding 2 fix — loader-table validation.** `agentc_ext_dyn_set_loader()`
  refuses (logs `ext: dynamic loader table incomplete, ignored`) any injected
  `AgcExtDynLoader` with a missing slot, so the active table is complete by
  construction; passing NULL restores the platform loader.
- **One shutdown-sweep warning.** When `agentc_ext_shutdown()` runs while an
  extension callback is on the stack, one warning covers the whole sweep (every
  mapping is kept mapped); a per-library warning is emitted only for the
  separate live-async-job case.
- **Not in the plan text:** the delivery is one `tests/dyn.sh` with
  `--mac`/`--windows`/`--wine` branches instead of `tests/dyn.sh` +
  `dyn-windows.sh`.

## P4.5b — platform runtime gate (delivered; gated on CI)

- `make ext-dylib`: native PIC shared object (`-fPIC -shared -nostdlib`; on
  macOS `-fPIC -dynamiclib -nostdlib`) exporting the canonical
  `agentc_ext_init` — no per-ident rename, because the runtime loader looks up
  that exact name.
- `make win-ext-dylib`: CRT-free `hello.dll` (`/dll /noentry /nodefaultlib
  /noimplib /export:agentc_ext_init`) plus a `nosym.dll` linked without the
  export, so the missing-symbol `GetProcAddress` path can be asserted without a
  compiler in the test script. `WIN_ARCH` selects the target.
- `tests/dyn.sh`: one platform-branched runtime gate. macOS (default on
  Darwin) builds `hello.dylib` and drives the native `dlopen`/`dlsym`/`dlclose`
  path; Windows (MSYS/MinGW/Cygwin) and Linux `--wine` build `hello.dll` and
  drive `LoadLibraryExW` (Wine injects `XDG_CONFIG_HOME` through a generated
  `.bat`, because Wine strips `XDG_*` from the Windows environment block);
  plain Linux builds `build/extensions/hello.so` as a PIC/ABI check and skips
  the runtime. Assertions: the dynamic row loads (`loaded … hello …
  (dynamic)`), `hello_echo` is really registered (a bogus name is rejected as a
  control), isolation (bad image / missing symbol / duplicate / invalid stem
  siblings) still loads `hello` and exits 0, the platform error text is
  asserted (`not a valid Win32 application (error 193)`, `procedure not found
  (error 127)`), the duplicate skip and the invalid-stem skip are asserted.
  Linux without Wine exits 0 after the build check.
- `make dyn-check` runs the Wine branch; `make win-ext-dylib` builds both DLLs.
- CI (`.github/workflows/ci.yml`): the `linux` job builds the shared object,
  the CRT-free DLLs and runs `make dyn-check` before the longer golden Wine
  suite; `macos-14` runs `make ext-dylib` + `sh tests/dyn.sh`; `windows-latest`
  runs `make win-ext-dylib` + `bash tests/dyn.sh --windows`.

## Deferrals (unchanged, not P4.5)

- The Linux freestanding static build stays static-only; no custom ELF loader.
- No signing/notarization/quarantine policy, no sandbox, no crash isolation: a
  dynamic extension is trusted native code with full process privileges.
- No permissions model beyond the POSIX write check, no join/wait on unload:
  the close is deferred until idle, never forced while busy.
