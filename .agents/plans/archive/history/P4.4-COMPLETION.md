# P4.4 — reserved points + completion (delivered)

Status: **P4.4a/b delivered, independently verified and committed (feature
commit + this docs commit).** The audit's F1 fail-closed fix and F2 caps-name
alignment landed before freeze (D137); the gate run and audit record is in
`EXTENSION-HANDOFF.md` §8. Decisions D125–D137 there.

## Goal

Close the remaining P4 seams: fix the stale app persistence state behind RPC
`set_model`/`new_session`, implement `tool_call.terminate`, wire the one
reserved point with a real feature (`session_before_switch` +
`session_start{reason:"new"}`), and complete the ranked hardening items.

## Frozen decisions (ratified; see D125–D133)

- **O-1 terminate (pi-exact):** only blocked calls may terminate; a batch
  terminates when every call in the assistant message was blocked with
  `terminate:true`. Mixed/normal calls keep the loop going.
- **O-2:** keep `agent_end` at `{stop_reason:"tool_use"}`; do not add a
  `terminated` field. A `turn_end.continue` still wins once (capped).
- **O-3 session points:** wire `session_before_switch` (`{"reason":"new"}`,
  first/replace/fail-closed, `{"cancel":true}` cancels) and emit
  `session_start{reason:"new", previous_session_file}` from `rpc_new_session`,
  **after** the persistence-state fix. Do **not** emit `session_shutdown` on a
  switch (extensions are process-lifetime).
- **O-4 `user_bash`:** keep reserved; document `rpc_bash` as the future site.
- **O-5:** extend `mcp_servers_change` with per-server `status` and advertised
  `caps`, and emit on failure as well as success.
- **O-6 MCP reconnect:** capped exponential backoff (1 s ×2, max 60 s) after
  `FAILED`, `AGENTC_MCP_RETRY_MS=0` disables and clamps the delay; `FAILED`
  stays non-pending so the startup budget is unaffected.
- **O-7 idle stdio drain:** bounded message drain in `READY`; EOF fails the
  server (pairs with O-6); HTTP has no idle channel (documented).
- **O-8 deferred:** prompts reload, OSC-11 theme detection, resumable extension
  HTTP, image/content channel, `user_bash`, per-step watchdog, progress ABI.
- **Reserved points stay reserved** where the feature does not exist
  (`session_info_changed`, `session_before_fork`, `session_before_tree`,
  `session_tree`, `cache_warming_decision`, `ui_prompt_*`, `user_bash`); they
  have no point-table entry, so `on` rejects them and `emit` is inert (see spec
  §4.1).

## P4.4a — correctness + parity (delivered)

1. **Stale persistence state fix — delivered.** `main.c` no longer keeps a
   front-end-local `PrintCtx`; `mio.observer = NULL` selects the ctx-bound
   `mode_flush_observer`, the compaction checkpoint/flush index moved to
   `agentc_mode_note_compaction()`, and `agentc_mode_rebind_session()`
   re-publishes the extension context/entry sink and reinstalls the observer
   after `rpc_new_session`. `agentc_mode_emit_session_start()` factors the
   `session_start` payload so the startup and new-session sites cannot drift.
2. **`tool_call.terminate` — delivered.** `int terminate` appended to
   `AgcToolVetoDecision`; the registry adapter parses it from the result and
   gates it on `block` (a `terminate` without `block` is logged at level 1 and
   dropped); the agent loop counts blocked+terminate calls and ends the
   submission after the batch/settle when every call in the assistant message
   agrees (cancel still wins; explicit `turn_end.continue` still re-enters once
   under the shared cap; `agent_end` keeps `stop_reason:"tool_use"`).
3. **`session_before_switch` + `session_start(new)` — delivered** per O-3.
   `session_before_switch` is `override/first/replace/fail-closed`; a blocked,
   failed, handled-without-decision or malformed result cancels, and a
   well-formed `{"cancel":false}` allows. The cancel gate runs before any file
   is touched and answers the RPC with
   `session switch cancelled by extension`.
4. Tests/goldens: `modes_test` (new_session/switch cancel+allow, set_model
   persistence, context follow), `agent_loop_test` (terminate all/mixed/
   continue/cancel), `ext_test` (adapter parse/gate, the point's caps/policy).
   Goldens regenerated.

### P4.4a delivered deviations (D134)

- **Injected transport survives a rebuild.** `agentc_agent_transport()` was
  appended to `include/agent.h`; `agentc_mode_rebuild_agent` reads the installed
  transport and re-installs it on the rebuilt agent (only when
  `transport.request` is non-NULL), so the app's replay/mock transport — and any
  embedder's injected one — survives RPC `set_model`.
- **Observer rebind is unconditional.** `agentc_mode_rebind_session` always
  reinstalls the observer (the io observer when a front end injected one after
  setup, else `mode_flush_observer`); the extension context/entry sink are
  re-published only when the mode installed the cooperative-abort wiring
  (`AGENTC_MODE_F_ABORT`), and cwd/system-prompt context fields are preserved
  (`agentc_ext_set_context` ignores NULL; an empty session file clears it).

## P4.4b — completion/hardening (delivered)

- In-flight extension HTTP cancel: `http_pump_one` passes the request's
  `cancelled` flag to the wire layer (`agentc_http_set_cancel`), so an
  already-running request is interrupted on its next poll slice and the
  callback receives `-ECANCELED` with the partial body decoded so far.
- MCP idle stdio drain: READY stdio servers are drained on every pump (at most
  64 complete messages per pump; leftovers stay buffered); EOF fails the server
  and arms the reconnect.
- `mcp_servers_change` payload: every non-NULL record with `name`, `kind`,
  `status` (`connecting`/`ready`/`failed`) and `caps` once initialize completed;
  emitted at record creation, on READY and on FAILED.
- MCP reconnect/backoff per O-6: `FAILED` servers rearm after
  `AGENTC_MCP_RETRY_BASE_MS` (1 s) doubled per failure, capped at
  `AGENTC_MCP_RETRY_MAX_MS` (60 s); `AGENTC_MCP_RETRY_MS` overrides the base
  (positive clamped to [1, 60 s], zero or negative disables, malformed keeps
  the default). A
  FAILED server is non-pending while it waits, so the startup budget is
  unaffected.
- Tests-only completions: failed-init rollback of commands/sections/status/
  pumps, `host->request_recompose` dirty bit, equal-priority hook ties, and the
  app-level late `mcp__` recompose selection.

### P4.4b delivered deviations (D135)

- **`--live-idle` driver.** The live idle-drain check is a `mcp_test` mode
  (`build/test/mcp_test --live-idle`) driven by `tests/mcp.sh`; the stdio mock
  grew `MCP_MOCK_IDLE_NOTIFY_MS` (a server-side timer that pushes
  `notifications/tools/list_changed` after a quiet tools/list round) and a
  stdout write lock for the timer thread.
- **`AGENTC_MCP_RETRY_MS` is the base**, not the whole schedule: it replaces
  `AGENTC_MCP_RETRY_BASE_MS`; the doubling and the 60 s cap are unchanged.
- **Private retry helper.** `agentc_mcp_retry_delay_ms()` is declared in
  `src/ext/mcp_int.h` (internal, exposed for `mcp_test`), not in `include/mcp.h`.
- **`ext_test` baseline warm-ups.** Before the allocator baseline, the fixture
  materializes the anthropic provider handle and touches the net-mock segment
  vector/capture buffer once, so process-lifetime caches reused by the new HTTP
  cancel test are not counted as leaks.
- **`--live-p2` runs with `AGENTC_MCP_RETRY_MS=0`** in `tests/mcp.sh`, keeping
  the existing live P2 scenario terminal on failure; the reconnect path has its
  own offline test (`mcp_test` `test_retry_reconnect`).
- **`retry_count` is not reset by a successful reconnect**: it is reset only
  when the record is created (`agentc_mcp_start`), so after the first failure
  the backoff shift accumulates per record (still capped at 60 s). The code
  comment says "consecutive failures"; the delivered behavior is
  failures-since-record-creation.
