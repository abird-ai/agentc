# P4.1 — typed custom providers (frozen design)

Status: **P4.1a and P4.1b delivered in the working tree; independent
verification and the commit are pending (P4.1c).** All twelve frozen decisions
(D-P1…D-P12) are implemented as written except the deviations recorded below.
Feeds `EXTENSION-SPEC.md` §11.1/§14 P4; decisions D81–D96 in
`EXTENSION-HANDOFF.md` (§5.5 is the per-file inventory). Read with: spec §2/§3
(ABI rules), §11.1 (delivered provider behavior), §12 (limitations), §13
(tests), the R1–R3 design records, and `src/prov/provider.h`.

## Goal

An extension registered during `init` can contribute a **named provider**: its
own wire protocol (request body + SSE mapping), auth style, base URL, path, and
optional static model metadata. The core keeps ownership of transport, retries,
timeouts, cancellation, `--record`/`--dump-wire`, `Content-Length`, header
sanitization and credential resolution.

## Frozen decisions

- **D-P1:** request data crosses the ABI as a host-materialised view
  (`AgcExtRequestView` + block/message/tool arrays), not as opaque internals or
  accessor host slots. One `agentc_alloc` per build attempt, freed after the call.
- **D-P2:** `build_request` writes head and body into **two opaque sinks**
  (`head_out`, `body_out`) using the existing `host->out_write`; the core inserts
  the blank line. A body containing `\r\n\r\n` can never confuse the split.
- **D-P3:** extension composition (`register_defaults`/`register_linked`/
  `apply_config`/`load_all`/summary) moves **above** provider resolution in
  `main.c`, so `--provider <ext>`, `--list-models` and model auto-pick see
  extension providers. Trust ordering is unchanged (load before trust).
- **D-P4:** provider rows are frozen until shutdown: a pointer vector of
  `ProviderRec *` (never moved), owner-tagged, and on unload marked `alive=false`
  instead of freed (MCP-frozen-entry lesson). Lookups skip retired rows; a handle
  still resolves to a retired row so an in-flight agent gets a clean
  `-ENOSYS`/`provider unloaded` error, and a retired row's name stays reserved
  until shutdown (a re-registration is refused with `-EEXIST`). No refcount in P4.1.
- **D-P5:** duplicate names are rejected (including presets); cap 64 providers.
  `add_provider` failure logs and does not fail `init` (same as `add_tool`).
- **D-P6:** the core applies auth from the resolved key according to the
  provider-declared `auth.kind` (`NONE`/`BEARER`/`HEADER`). The key is **never**
  in the request view and never reaches the extension. `QUERY` is reserved and
  rejected in P4.1 (clear log).
- **D-P7:** SSE only. Extensions receive parsed `AgcExtWireEvent`s and call a
  typed `AgcExtStreamSink`; arbitrary framing (`stream_bytes`) is a later append.
- **D-P8:** `stream_open`/`stream_finish`/`stream_close` are optional (NULL =
  stateless/default); `build_request` and `stream_event` are mandatory.
- **D-P9:** static model metadata is registered at `add_provider` and marked
  static so `agentc_model_clear_dynamic` cannot wipe it; the shared 256-slot
  dynamic cap is respected with a one-time log when full.
- **D-P10:** generic `providers.<id>`/`api_keys.<id>` config entries (user
  scope only, ≤32) in addition to the four named presets.
- **D-P11:** discovery reuses the existing styles `NONE/DEFAULT/ANTHROPIC/OLLAMA`;
  `CUSTOM` (extension parser) is deferred and reserved. Discovery auth follows
  the row's auth style (internal `auth_headers` hook; NULL = Bearer).
- **D-P12:** custom rows use `api = name`; sharing an existing wire api is
  deferred. Cost rates, per-model thinking config, multimodal, OAuth providers
  and `providers.<id>.headers` are deferred.

## Delivered implementation record

Both phases landed in the working tree; `git status` shows the whole P4.1 change
set uncommitted. P4.1a: ABI + registry + internal adapter + Rust mirror +
`ext_test`. P4.1b: app reorder, discovery/models/config, `extensions/fake_provider`,
`agent_loop_test`/`config_test`/`e2e.sh`/`ext.sh`. The clean-tree gate run and the
independent verification are complete (P4.1c): all requested gates are green.
The audit found one major violation, fixed before freeze — AUTH_NONE discovery
sent `authorization: Bearer` whenever a key resolved; an empty `auth_headers`
override is now authoritative — plus five minors, also fixed: retired provider
names are reserved (a held handle can never be redirected to a re-registered
provider), `sink_usage` is `FIELD_OK`-gated, base-URL/auth-header/env-key strings
are bounded, static models print as `static` rather than `discovered`, and
`tests/e2e.sh` forces the stock binary so a prior `release-exts` cannot break it.

### P4.1a deviations (inside the frozen rows they touch)

- **`clear_static` (D-P9).** Static rows survive `agentc_model_clear_dynamic`,
  but the provider-record free path must be able to drop them, so
  `agentc_model_clear_static(provider)` was added (`include/agent.h`,
  `src/prov/models.c:119`); `provider_rec_free` calls it
  (`src/ext/registry.c:2081`). A dynamic re-registration of the same provider+id
  updates the numeric fields but never clears `AGENTC_MODEL_STATIC`
  (models.c:41).
- **`provider_open_ops` tracking (D-P1/D-P4).** `stream_open(st)` does not receive
  the row, so `agentc_stream_state_init` tracks the row **before** `stream_open`
  (`src/prov/provider.c:348`) and exposes `agentc_provider_open_ops(st)`
  (provider.c:333); the extension adapter recovers its `ProviderRec` that way
  (`registry.c:2429`). The open-stream table moved to the top of provider.c so
  `registry_reset` can release it.
- **`provider_all` rows (D-P11).** The app enumerates live providers through the
  new count-first, name+api-deduplicated `agentc_provider_all`
  (`src/prov/provider.h:71`, `src/prov/provider.c:234`) instead of a hardcoded
  name list: `--list-models`, the onboarding menu and the unknown-provider
  diagnostic. `openai` stays two rows (chat + codex).
- **`registry_reset` scope (D-P4).** `agentc_provider_registry_reset()` now
  returns the registry to its pristine baseline: with no live stream it frees the
  dynamic row vector and the open-stream table and unseeds the builtins so they
  re-seed lazily (`src/prov/provider.c:169`). The new
  `agentc_provider_retire_ext()` (provider.c:193) marks every ext row retired;
  `agentc_ext_shutdown` calls it, then the reset, then frees the records
  (`src/ext/registry.c:3047–3057`). Builtin rows and their handles are static and
  stay stable.
- **Bearer default prefix (D-P6).** Registration fills a BEARER row's missing
  header with `Authorization` and a missing prefix with `"Bearer "`
  (`registry.c:2632–2637`); an AUTH_HEADER row must declare a token-safe header,
  and its prefix (if any) is prepended verbatim; `AUTH_QUERY` is rejected.
- **Static rows lifetime (D-P9).** Static rows are owned by the provider record
  and dropped when it is freed; the shared 256-slot table logs `model: registry
  full` once (models.c:66) and `agentc_model_is_static()` exposes the flag
  (models.c:143). This is the one piece of host-side model state a provider
  contribution owns.

### P4.1b deviations

- **Onboarding composition order.** The composition block runs before onboarding
  as well as before provider resolution: `agentc_main` composes at
  `src/app/main.c:546–557` (after the endpoint context, before the first-run
  onboarding at :561–575), and the `agentc setup` subcommand composes
  `register_defaults(true)`/`register_linked`/`apply_config`/`load_all` around
  `agentc_setup_onboard` and shuts down after (main.c:344–354). MCP is skipped in
  the subcommand so setup cannot start a server. The frozen D-P3 text named only
  the provider-resolution move.
- **Preset-seeding helper.** `agentc_setup_list_models` cannot see the
  lazily-materialized OpenAI-compatible presets through `agentc_provider_all`, so
  `seed_presets()` materializes the seven preset names (and any generic
  `providers.<id>` id) first (`src/app/setup.c:194`);
  `agentc_setup_provider_names` (setup.c:204) shares it. This replaces the old
  hardcoded names array.
- **e2e stock-binary skip.** `tests/e2e.sh` probes `--provider fake --list-models
  --offline` only when the binary links the manifest entry; the stock
  `build/agentc` links none, so that case prints `skip` with the reason instead
  of failing (tests/e2e.sh:150–164). The real assertion runs against
  `build/ext_harness` in `tests/ext.sh`.
- **Harness coverage.** The linked `fake_provider` cannot run in the plain golden
  fixture, so its coverage is `tests/ext_test.c` harness mode (built by
  `make ext-pipeline` into `build/ext_harness`, run by `tests/ext.sh`):
  registration + static model, sanitized request head + core auth + body, a
  canned SSE stream and the `--list-models` line. The golden fixture covers the
  `provfix` row instead; `tests/agent_loop_test.c` covers the loop paths (view,
  round-trip, error, retry, cancel, unload, discovery auth, enumeration) and
  `tests/config_test.c` the generic config.

### Deliberate deferrals (recorded, not built)

- `AGENTC_EXT_AUTH_QUERY` (query-parameter auth) is reserved and rejected at
  registration.
- No extension-owned discovery parser: `CUSTOM` is not in the discover enum; the
  styles are `DEFAULT`/`ANTHROPIC`/`OLLAMA`/`NONE`.
- SSE-only stream mapping; there is no raw-framing/`stream_bytes` hook.
- No cost rates in `AgcExtProviderModel`: `agentc_model_cost` returns 0 for an
  extension model (`src/prov/models.c:185`).
- No per-model thinking config and no multimodal request channel (the model
  `image` flag is metadata only; the view is text/thinking/tool-call).
- No OAuth providers; auth is a core-applied header.
- Generic config covers `providers.<id>.base_url` and `api_keys.<id>` only;
  `providers.<id>.headers` is not parsed.
- Custom rows use `api = name`; sharing an existing wire api is deferred.
- No reference counting for retired rows: the record lives until
  `agentc_ext_shutdown`.
- The rest of P4 stays demand-gated: async extension tools, more reserved
  points, an extension-built skills/MCP-resources layer, optional dynamic
  loading on macOS/Windows.

## ABI additions (`include/agentc_ext.h`, append-only)

Role/block/stop/discover/auth/usage constants; structs:

```c
typedef struct AgcExtBlockView  { uint32_t struct_size; uint32_t type; const char *text;
                                  size_t text_len; const char *tool_id; const char *tool_name;
                                  const char *tool_args; } AgcExtBlockView;
typedef struct AgcExtMessageView{ uint32_t struct_size; uint32_t role; int32_t stop_reason;
                                  const AgcExtBlockView *blocks; size_t nblocks; } AgcExtMessageView;
typedef struct AgcExtToolView   { uint32_t struct_size; const char *name; const char *description;
                                  const char *parameters_json; uint32_t flags; } AgcExtToolView;
typedef struct AgcExtRequestView{ uint32_t struct_size; const char *provider; const char *model;
                                  const char *system; int32_t thinking_level; int64_t max_tokens;
                                  const AgcExtMessageView *messages; size_t nmessages;
                                  const AgcExtToolView *tools; size_t ntools; } AgcExtRequestView;
typedef struct AgcExtProviderAuth  { uint32_t struct_size; uint32_t kind; const char *header;
                                     const char *prefix; } AgcExtProviderAuth;
typedef struct AgcExtProviderModel { uint32_t struct_size; const char *id; const char *name;
                                     uint32_t ctx_window; uint32_t max_tokens; int reasoning;
                                     int image; } AgcExtProviderModel;
typedef struct AgcExtStream { uint32_t struct_size; void *ud; } AgcExtStream;
typedef struct AgcExtUsage  { uint32_t struct_size; uint32_t fields;
                              uint32_t input, output, cache_read, cache_write, reasoning; } AgcExtUsage;
typedef struct AgcExtWireEvent { uint32_t struct_size; const char *event; const char *data;
                                 size_t data_len; } AgcExtWireEvent;
typedef struct AgcExtStreamSink {
    uint32_t struct_size;
    void (*text)(AgcExtStream *st, const char *p, size_t n);
    void (*thinking)(AgcExtStream *st, const char *p, size_t n);
    void (*tool_start)(AgcExtStream *st, const char *id, const char *name);
    void (*tool_args)(AgcExtStream *st, const char *p, size_t n);
    void (*response_id)(AgcExtStream *st, const char *id);
    void (*usage)(AgcExtStream *st, const AgcExtUsage *u);
    void (*stop)(AgcExtStream *st, int reason);
    void (*error)(AgcExtStream *st, const char *message);
} AgcExtStreamSink;
typedef struct AgcExtProvider {
    uint32_t struct_size;
    const char *name; const char *label; const char *default_base_url; const char *path;
    const char *env_keys[3];
    int needs_key; int discover_style;
    const AgcExtProviderAuth  *auth;
    const AgcExtProviderModel *models; size_t nmodels;
    void *ud;
    int  (*build_request)(const AgcExtHost *, const struct AgcExtProvider *,
                          const AgcExtRequestView *, void *head_out, void *body_out);
    int  (*stream_open)(const AgcExtHost *, const struct AgcExtProvider *, AgcExtStream *);
    int  (*stream_event)(const AgcExtHost *, const struct AgcExtProvider *, AgcExtStream *,
                         const AgcExtWireEvent *, const AgcExtStreamSink *);
    int  (*stream_finish)(const AgcExtHost *, const struct AgcExtProvider *, AgcExtStream *,
                          const AgcExtStreamSink *);
    void (*stream_close)(const AgcExtHost *, const struct AgcExtProvider *, AgcExtStream *);
} AgcExtProvider;
```

Host slot appended after `set_title`:
`void (*add_provider)(const AgcExtProvider *provider);`

Rules: registration copies every string and the auth/model arrays; the view and
wire event are borrowed for the call; `head_out`/`body_out` are opaque — write
with `host->out_write`; `st->ud` is extension state allocated with
`host->alloc` and released in `stream_close`; `text`/`thinking`/`tool_args`
payloads are copied by the sink (never retain the JSON scratch).

## Registry/adapter

- Registry `host_add_provider`: validate `struct_size` (covers `stream_close`),
  name charset/≤64, `path` `/`-leading without CR/LF/space, `default_base_url`
  parses http/https, auth header token-safe, model ids/limits, cap 64;
  duplicate via `agentc_provider_by_name`; copy into a stable `ProviderRec`;
  fill `AgcProviderOps` (`is_ext`, `ext_rec`, `auth_headers`), register and
  materialise the stable handle.
- Request adapter: skip non-serialisable/empty assistant turns and
  `AGENTC_TOOL_HIDDEN` tools; materialise the view; call the extension; sanitize
  head (CRLF→space, drop `Host`/`Content-Length`/`Transfer-Encoding`, drop the
  declared auth header); append core auth; join head + blank line + body.
- Stream adapter: `ExtStreamRec` in `st->priv`; static sink context saved/restored
  around callbacks; `map_sse` → `AgcExtWireEvent` → `stream_event`; `finish`
  applies the built-in resolve/validate; `close` calls the extension then frees.
- Lifecycle: `alive` checked before every callback; `owner_remove` retires rows;
  `agentc_ext_shutdown` calls `agentc_provider_registry_reset()` then frees
  records; no provider callback runs after shutdown (main teardown order).

## App/core integration

- `main.c`: composition block above provider resolution (D-P3);
  `--list-models` early return calls `agentc_ext_shutdown()`; unknown-provider
  diagnostic lists loaded provider names; `--help` note.
- `setup.c`: `agentc_setup_list_models` enumerates live provider rows
  (`agentc_provider_all`, dedup by name+api as today) instead of the hardcoded
  names list; onboarding appends extension providers (optional in P4.1).
- `config.c/h`: generic `providers.<id>`/`api_keys.<id>` entries; getters check
  named presets first.
- `models.c/agent.h`: `AgcModel.flags` appended + `agentc_model_register_static`
  + static-preserving clear + `agentc_model_is_static`.
- `discover.c`: per-row `auth_headers` (NULL = Bearer).
- `mode_rpc.c`: no changes required; add tests.
