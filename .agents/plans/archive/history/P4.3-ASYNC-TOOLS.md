# P4.3 — asynchronous extension tools (delivered)

Status: **P4.3a (ABI + `AgcJob.cleanup` + adapter/retire discipline + Rust
mirror + `ext_test`/`jobs_test`) and P4.3b (`async_demo` + `ext.sh` +
`agent_loop_test` + goldens) are implemented, independently verified and
committed (feature commit + this docs commit).** The audit's two memory-safety
findings and the harness-timeout nit were fixed before freeze (D124). Decisions
D110–D124 in `EXTENSION-HANDOFF.md`; behavior in spec §3.7/§12–§16 and
`.agents/docs/30-extensibility.md` §3.7. Read with the appended-ABI rules
(`FIELD_OK`/`HOST_HAS`/`required_host_size`) and the internal job driver
(`src/core/tools/jobs.h`).

## Goal

An extension tool may be asynchronous: the host drives `start` then zero or
more `step` calls on the main loop; the extension streams output and completes,
fails, times out or is cancelled, and always tears down through one `stop`.

## Frozen decisions

All twelve are delivered as frozen except where "Delivered deviations" below
says otherwise.

- **D-A1:** append `start`/`step`/`stop` to `AgcExtTool`; no new contribution
  struct or host slot. `run != NULL` ⇒ sync and the async trio is ignored
  (level-1 log); `run == NULL` requires the complete trio.
- **D-A2:** `stop(state, reason)` is mandatory and called exactly once for every
  `start` that returned `>= 0`. Reasons: `FINISHED`, `ERROR`, `TIMEOUT`,
  `CANCELLED`, `UNLOAD`. No separate cancel callback; cancellation is polled via
  `host->is_cancelled(signal_token)` and delivered as `stop(CANCELLED)`.
  `FINISHED` means "no more steps", not success (`*is_error` is the result).
- **D-A3:** `void *state` is extension-owned (`host->alloc` in `start`, freed in
  `stop`); the host never frees it. The host owns only its adapter record.
- **D-A4:** step output goes through a per-step staging buffer into
  `agentc_tool_append_output` (50 KB inline cap + spill, 2000-line display cap).
- **D-A5:** append an optional `AgcJob.cleanup(self, job, reason)` hook, set by
  the adapter in `start` and invoked exactly once by the driver on
  cancel/timeout/fatal/release; reasons mirror the tool stop reasons.
- **D-A6:** a `ToolRec` with live async jobs is unlinked from `g_tools` but not
  freed until `agentc_ext_shutdown` (`retired` flag + retired list);
  `owner_remove` calls `stop(UNLOAD)` for each live job before `shutdown()`.
  Retired tool names may be reused (no name lookup reaches the old record).
- **D-A7:** `run` wins when both are declared.
- **D-A8:** one 32-byte signal token per job; the adapter sets the existing
  `g_signal`/`g_signal_cancel` window around every extension callback.
- **D-A9:** the adapter calls `agentc_pump(0)` after each running step (extension
  off the stack) so `defer`/`http_request` work progresses.
- **D-A10:** async tools are not implicitly sequential.
- **D-A11:** Rust mirror gains the three fields now (compile requirement).
- **OD-3:** async `timeout_ms` clamps to `AGENTC_EXT_TOOL_TIMEOUT_MAX_MS`
  (1 800 000 ms) with a level-2 log; sync unchanged.

## ABI

Append after `run` in `AgcExtTool`:

```c
#define AGENTC_EXT_TOOL_FINISHED  0
#define AGENTC_EXT_TOOL_ERROR     1
#define AGENTC_EXT_TOOL_TIMEOUT   2
#define AGENTC_EXT_TOOL_CANCELLED 3
#define AGENTC_EXT_TOOL_UNLOAD    4

    int  (*start)(const AgcExtHost *host, const struct AgcExtTool *self,
                  const AgcExtToolCall *call, void *out, bool *is_error,
                  void **state);
    int  (*step)(const AgcExtHost *host, const struct AgcExtTool *self,
                 const AgcExtToolCall *call, void *state, void *out,
                 bool *is_error);
    void (*stop)(const AgcExtHost *host, const struct AgcExtTool *self,
                 void *state, int reason);
```

Codes: `start` 0 running / 1 complete / `<0` fatal (no `stop` on `<0`); `step`
0 running / 1 complete / `<0` fatal. Host drives all calls on the main loop;
`start`/`step` must not block — I/O goes through `host->defer`/`http_request`
(serviced between steps); the signal token is valid from `start` through `stop`.

## Driver/adapter

- `AgcJob.cleanup` appended in `jobs.h`; invoked before the driver frees
  `job->priv` on cancel/timeout/fatal/release (cleared before calling).
- Adapter (`registry.c`): `ExtAsync { rec, call copy, cancel, token[32],
  ext_state, stopped, next/prev }` in `job->priv`; `ext_tool_start/step` restore
  the owner, set the signal window, flush staging output, and map return codes;
  `ext_tool_cleanup` maps the driver reason and calls `stop`.
- A retired record observed on a later step synthesizes
  `"error: extension tool unloaded"` with no extension call.
- Errors are tool-result errors (transcript `tool` message with `is_error`), not
  agent failures; abort still ends the run with `last_error = "aborted"`.
- Retire rules apply to `owner_remove` and `agentc_ext_remove_tool_internal`;
  internal async tools (bash) are unaffected.

## Security / limits

- Extension state size is extension-owned (documented soft cap); output is
  bounded by the existing streaming/truncation path; timeout bounds a stuck
  tool; a blocking `start`/`step`/`stop` cannot be preempted (documented
  residual, same class as a blocking sync `run`).
- `stop` must not register contributions and should not block.

## Delivered deviations (P4.3a/b)

- **P4.3c verification fixes (D124).** The audit found and the wave fixed two
  memory-safety defects: (1) a `ToolRec` could be freed while its own `start`
  was on the stack (teardown reachable from `start` via a hook or the internal
  API); the job is now linked before `start`, a not-yet-started job still counts
  as live so teardown retires/`free_pending`s without calling `stop`, and the
  trampoline finishes the retirement after `start` returns (a failed start
  unlinks with no `stop`); (2) `job_fatal`/`job_timeout` formatted `tool->name`
  after `job_cleanup` may have released the record; the message is now built
  before cleanup. `tests/ext.sh` and `check-ext` bound the harness at 30 s.
  Regression tests reproduce both probes and fail when the fixes are reverted.

- **P4.3a — shutdown defers the free.** `agentc_ext_shutdown` cannot free a
  retired record while a live async job still points at it through `tool.ud`.
  The delivered code marks such a record `free_pending` and the **last job's**
  unlink releases it (`ext_async_unlink`, `src/ext/registry.c`); a retired
  record with no live jobs is freed during shutdown exactly as D-A6 specified.
  `ext_test`'s `async_shutdown_*` checks pin the mid-shutdown path.
- **P4.3b — fatal step index 2.** `async_fatal` returns `-5` (EIO) on its third
  step (`i == 2`, after streaming `fatal step 0`/`fatal step 1`), so the generic
  fatal path replaces the staged output with
  `error: tool 'async_fatal' failed to run (-5)` and delivers `stop(ERROR)`.
- **P4.3b — `fail_at` replaces the failing step line.** `async_demo
  {steps:N, fail_at:K}` never emits the normal `step K` line: at `K` it emits
  `error: demo failed at K`, completes and sets `*is_error`; the stop reason is
  `FINISHED` because the error is the tool result, not the stop reason.
- **P4.3b — debug/test surface.** The example registers the `async-demo-debug`
  command (per-tool `starts`/`steps`/`stops`/`reason`/`polled` counters;
  `{"reset":true}` clears them). `ext_test`'s harness drives the linked example
  through it, so the golden fixture binary does not link the example.
- **P4.3b — the poll branch is covered by a direct adapter drive.** The job
  driver checks the batch cancel flag before every step (`run_parallel`,
  `src/core/tools/jobs.c`), so a driver-driven `async_cancel` always stops
  `CANCELLED` before the extension's own `host->is_cancelled` poll can run.
  `harness_async_checks` therefore drives `start`/`step` directly with the token
  already cancelled (the harness owns `job.priv`, exactly as `jobs_release`
  would) to cover the documented poll branch: partial output + `*is_error`,
  `stop(FINISHED)`, `polled=1`.
- **P4.3a — no generic line cap.** D-A4 mentioned a 2000-line display cap; the
  generic async path as delivered applies the 50 KB inline cap plus
  spill/truncation (`agentc_tool_append_output`/`agentc_tool_finalize_output`,
  `AGENTC_LIMIT_TOOL_BYTES`). The 2000-line cap (`AGENTC_LIMIT_TOOL_LINES`) is
  applied by `bash`/`read` themselves and is not part of the extension-tool job
  path.

## Tests

- `ext_test`: registration gates (async-only, partial trio rejected, `run`+async
  ignores the trio, a baseline-size struct with `run` stays sync while async
  fields beyond its declared `struct_size` are not read and the tool is rejected
  as an incomplete trio), incremental output, `is_error`,
  fatal/timeout/cancel/unload — exactly one `stop` with the right reason,
  retired-count/dirty behavior, allocator baseline.
- `jobs_test`: cleanup on fatal/timeout/cancel/release, before `job->priv` is
  freed.
- `agent_loop_test`: an async fixture through the loop (events, transcript,
  timeout tool result + next turn, abort, two-tool interleave without wall-clock
  assumptions).
- Example `extensions/async_demo`: completing/failing/timeout/cancel tools;
  `tests/ext.sh` harness checks; Rust crate compile.
- Goldens regenerated; the P4.3 gate is `make check`, `tests/ext.sh`,
  `tests/e2e.sh`, `tests/mcp.sh` and the `make windows` cross-build — not yet
  recorded green (P4.3c).
